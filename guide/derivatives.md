# 파생 콘텐츠 (노트·링크드인·인스타그램 이미지·커뮤니티·데이터 카탈로그)

뉴스레터가 확정된 뒤, 요청이 있을 때만 만든다. 릴스는 [motion.md](motion.md)에 따로 있다. 데이터 카탈로그의 엑셀은 리드 차트를 별도 제작하는 호라면 초안과 함께 만든다.

- 모든 파생 콘텐츠 게시는 다음 뉴스레터 발행일(수요일) 전에 마친다. 게시일은 공휴일·연휴를 피해 평일 오전으로 잡는다.
- 리드 차트와 리드 문단은 그대로 링크드인 게시물의 재료이고, 리드 차트 파일은 그대로 인스타그램 이미지 게시물이며, 리드 차트의 데이터는 릴스의 원본이다.

## 노트

- 목적: 검색 유입용 스낵 콘텐츠. 단어 정의나 특정 현상을 1~2분 안에 읽히게 정리한다.
- 소재: 뉴스레터와 같은 원자료 안에서, 뉴스레터가 다루지 않은 흥미롭고 특징적인 부분을 고른다. 특징이 여러 개면 한 편에 묶지 말고 각각 별도 포스트로 쓴다. 뉴스레터에서 덜어낸 지표 정의·방법론도 노트 소재다.
- 형식: H3 소제목과 구분선이 없는 담백한 줄글. 첫 문단에 검색한 사람이 찾는 답을 먼저 쓴다(검색 결과 요약에 첫 문단이 노출되기 때문).
- 뉴스레터를 인용하거나 연결해도 된다.
- 마지막 문단에 출처를 적는다. 원문의 인용 조건도 반영한다.
- 노트마다 제목, URL, 메타 제목, 메타 설명, 노리는 검색어를 함께 제시한다.
- URL은 검색어를 영어로 옮긴 슬러그로, 연도 없이 쓴다(예: what-is-forward-deployed-engineer).

## 링크드인 피드

기준은 10월 14일 발행호의 게시물이다([examples/2026-10-14-education-at-a-glance.md](examples/2026-10-14-education-at-a-glance.md) 끝).

- 본인 개인 계정에 올리는 글이다. '웬즈데이터'가 아니라 '나'를 주어로 쓴다.
- 주 1회 올리되, 올리는 날은 정해 두지 않고 시간이 날 때 올린다. 노트를 하나하나 따로 소개하지는 않는다.
- 구성: 본문(제목 한 줄 → 번호 문단 3~4개 → 뉴스레터로 잇는 한 문장)에 리드 차트 이미지 한 장을 붙이고, 원문 링크는 첫 댓글에 단다. 영상은 올리지 않는다.
- 첫 줄: 리드 차트 제목을 그대로 옮기지 않는다. 피드 미리보기에 보이는 첫 3줄(첫 줄 + 1번 문단 첫머리)이 읽을지를 결정하므로, 첫 줄은 독자가 궁금해하거나 흔히 믿는 지점을 그 호의 데이터로 건드리는 한 문장으로 쓴다(흔한 믿음을 숫자로 뒤집거나, 독자의 질문에 의외의 답을 준다). 본문에서 확인된 사실과 숫자만 쓰고, 과장·낚시성 표현·물음표 남발은 피한다. 모바일에서 두 줄을 넘지 않게 쓴다. 1번 문단의 처음 질문이 첫 줄과 자연스럽게 이어지게 한다.
- 초안을 줄 때 다른 지점을 건드리는 첫 줄 대안 2개를 함께 준다. 리드 차트의 제목은 바꾸지 않는다.
- 오글거리는 자기 서술은 쓰지 않는다. 금지 예: "제가 처음 붙잡은 질문이었습니다", "그 질문을 내려놓고", "가장 와닿은 문장이었습니다", "~를 펼치며", "남은 질문은 ~입니다". 질문은 붙잡았다고 말하지 말고 바로 던지며(예: "대학 졸업장은 월급을 얼마나 올려 줄까요? OECD 교육지표 2026을 보며 이것부터 따져 봤습니다."), 생각의 흐름은 무엇을 확인했고 무엇을 찾았는지를 담담하게 적는 것으로 드러낸다.
- 번호 문단은 뉴스레터를 쓰며 실제로 거친 생각의 흐름을 따른다. 처음 떠올린 질문 → 데이터에서 발견한 반전 → 원문이 짚는 이유 → 독자에게 남기는 질문 순서다.
- 핵심 수치는 1~2개만 쓴다. 경험과 감정은 실제로 있었던 것만 쓰고 지어내지 않는다.
- 출처(기관, 집필자명 등)는 본문 문장 안에 녹인다. '자료:' 같은 별도 표기는 하지 않는다.
- 마무리: "이 질문에 이르기까지의 이야기는 뉴스레터에 조금 더 길게 적어 두었습니다." 같은 한 문장으로 끝낸다. 본문에는 URL을 넣지 않는다.
- 첨부: 그 호의 리드 차트 이미지 한 장(뉴스레터에 쓴 파일 그대로)을 붙인다. 릴스가 있는 호도 영상은 올리지 않는다.
- 첫 댓글: 게시하자마자 본인 계정으로 '📌 원문 보기: {뉴스레터 URL}?ref=linkedin' 한 줄을 단다. 본문에 이미지를 붙이면 링크 미리보기 카드가 생기지 않지만, 댓글의 링크에는 카드가 생긴다.
- 쓰지 않는 것: 본문의 이모지(첫 댓글의 📌만 예외), 해시태그, 서비스 소개체("이번 주 웬즈데이터에서~"), 요약 목록, "공감하면 댓글" 같은 참여 유도 문구

## 인스타그램 이미지 게시물

- 목적: 리드 차트 한 장을 인스타그램 피드에 그대로 올린다. 매주 한 번 계정에 무언가가 올라가는 리듬을 만드는 기본 게시물이고, 릴스는 움직임이 있는 호에만 더한다. 기준은 10월 24일에 올린 OECD 교육지표 2026 리드 차트다(그리드에서 3:4가 잘리지 않고 통째로 들어가고, 제목·손글씨·주인공·로고가 썸네일에서 읽혔다).
- 규격: 리드 차트 파일(1080×1440, 3:4)을 그대로 쓴다. 따로 만들지 않는다. 올리기 전에 프로필 그리드 미리보기에서 왼쪽 위 축 이름과 오른쪽 아래 로고가 잘리지 않는지 본다.
- 캡션: 캡션 한 줄(결론) → 축·지표 정의와 장기 기준점 → 해석 한두 문장(차트가 보여 주는 범위 안에서) → 뉴스레터 안내 한 문장("프로필 링크에서") → 출처 한 줄(기관, 「공식 명칭」, 발표일, 표 번호). '더 보기' 앞에 보이는 첫 줄은 글을 드는 숫자가 앞에 오게 쓴다. 이모지는 쓰지 않고, 해시태그는 끝에 3~5개만 둔다.
- 올리는 날: 뉴스레터 발행 당일(수요일) 오전. 같은 호에 릴스가 있으면 이미지를 먼저 올리고 릴스는 그 뒤 다른 평일에 올린다. 지난 호의 리드 차트를 몰아 올릴 때는 하루 한 장씩 평일 오전으로 예약한다.
- 캐러셀(선택): 릴스를 만들 수 없는 호는 둘째 장에 캡션 한 줄을 큰 글씨로 둔 캐러셀로 올려도 된다. 아직 시험하지 않았다.
- 산출물: 따로 만들지 않는다. 리드 차트 파일과 캡션 텍스트를 Drive '21. Instagram/{날짜}_{주제}' 폴더에 둔다.

## 커뮤니티 공유 — 주제가 맞는 호만

- 긱뉴스(news.hada.io): AI·기술 주제일 때만 올린다. Show GN이 아니라 일반 뉴스로 등록한다. 사실 중심의 제목에 개조식 요약 5~6줄을 붙인다. 같은 출처를 반복 등록하면 제한될 수 있으니 자주 올리지 않는다.
- 커리어리(careerly.co.kr): 커리어·일자리 주제일 때 올린다. 링크드인과 겹치지 않는 문구로 3~4문단을 쓰고 링크를 붙인다.
- 모든 링크 끝에는 ?ref=채널명을 붙인다.

## 데이터 카탈로그

- 기준: 10월 18일 OECD 교육지표 데이터 포스트와 10월 23일 산업연관표 데이터 포스트. 본문은 짧게 두고, 데이터·변수 설명·정보는 엑셀 한 파일에 담는다. 본문에 변수 설명 표를 넣지 않는다.
- URL: /data/{주제}-{지표}-{시작연도}-{종료연도}. 태그는 '데이터'.
- 제목: '{범위} {지표1}·{지표2} 데이터: {공식 데이터명}'(예: 산업별 취업유발계수·고용유발계수 데이터: 2024년 산업연관표).
- 본문 구성: 소개 한 단락(발표일·기관·자료명과 무엇을 정리했는지, 필요하면 핵심 지표의 뜻 한 문장) → 관련 뉴스레터 북마크 카드 → 구분선 → 굵은 라벨 불릿 네 개(출처·기간·범위·참고. 출처는 원문 페이지에 링크, 참고에는 가격 기준 같은 비교 주의점과 '변수 설명과 이용 조건은 파일 안 시트에 있다'는 안내) → 구분선 → 파일 카드(엑셀 한 파일).
- Ghost 메타: 메타 제목·메타 설명·발췌문·노리는 검색어를 프로젝트 지침 3장 [Ghost 메타 데이터] 규칙대로 함께 쓴다.
- 파일: 엑셀(.xlsx) 한 파일. 파일명은 URL 슬러그를 영문 snake_case로 바꾼 이름(예: korea_industry_employment_inducement_2020_2024.xlsx). 시트는 셋이다.
  - '데이터': 머리행 굵게·옅은 회색(#F2F2F2), 서체 Arial 10, 코드·이름 열 고정, 필터. 숫자는 원문 값 그대로 두고 표시 형식으로만 자릿수를 맞춘다.
  - '변수 설명': 변수 / 이름 / 설명 / 단위 / 기준연도 / 원문 표(원문에 쪽 번호가 있으면 '쪽' 열을 더한다).
  - '정보': 데이터 / 출처(공식 명칭·링크) / 발표일 / 범위 / 기준연도 / 읽는 법(대표 값 하나로 지표 뜻 풀이, 필요할 때) / 빈칸과 기호 / 원문과 달라진 점 / 이용 조건 / 기관 고지(원문이 요구할 때) / 인용 예 / 관련 글 / 정리(웬즈데이터, 연월).
- 이용 조건: 원문 라이선스를 직접 확인한 경우에만 적는다(예: OECD는 CC BY 4.0과 OECD 고지문). 확인하지 못하면 라이선스를 적지 않고, 원자료 출처를 함께 밝혀 달라고만 쓴다.
- 데이터 만들기: 리드 차트를 별도 제작하는 호는 이 파일을 만든다. 차트 한 장을 그리고 버리는 파일이 아니라 독자에게 공개되는 자료다.
  - 컬럼명은 영문 snake_case로 '지표_대상_연령_연도_단위'처럼 뜻이 드러나게 짓는다(예: nonformal_training_employed_25_44_2023_pct).
  - 행은 비교 대상 전체(OECD면 회원국 전부 + OECD 평균 행, 산업이면 전 산업·묶음 부문·세부 부문)를 넣고, 코드(국가는 ISO3)·영문명·한글명을 둔다.
  - 차트에 쓴 지표 외에도 같은 원문 표의 관련 지표(성별·연령대별·시계열 비교값 등)를 넣어 자료의 쓰임을 넓힌다.
  - 원문 기호(b 시계열 단절, c 표본 부족, d 다른 범주 포함, m 결측, x 다른 열에 합산, 1) 같은 각주 번호 등)는 값에서 떼어 data_flags 열에 '열이름:기호'로 적고, 여러 개는 ;로 구분한다. 같은 지표의 모든 연도 열에 붙는 기호는 열이름 끝을 *로 줄여 쓴다(예: employment_inducement_coef_*:1)). 기준연도가 다른 나라 등 각주는 notes_ko 열에 적는다. 값 칸에는 숫자만 둔다.
  - 계산해 만든 열(순위, 차이 등)은 이름에 calc_를 붙이고 엑셀 수식으로 넣는다. 수식을 넣은 뒤 다시 계산해 오류가 없는지 확인한다.
- 보관: Drive '13. Data/{번호}. {포스트 제목의 데이터명 부분}' 폴더에 엑셀 한 파일만 둔다(번호는 001부터 이어서).
